3D Printed Eddy-Current Leveling Coil — Little Crab Bed Scanning Coil

Author: 仁泉之子
1. 3D-printer eddy-current leveling — contactless bed scanning that is fast and precise, a leveling method that is not to be missed;
2. This project aims to implement bed scanning with Klipper's built-in eddy driver. It only needs I2C communication — even boards without hardware I2C can use any two IOs for software I2C. Make sure the I2C pins have no capacitors, diodes, or large series resistors attached. No CAN or USB communication needed, wiring is simplified, any toolhead works, and the firmware upgrades together with your Klipper version;
3. The board comes in a coil-only version and a coil with an onboard LDC1612. The coil-only version is for toolheads with an integrated LDC1612 chip (the STM32F446 Little Crab toolhead); the version with the integrated LDC1612 works with any toolhead. Keep the coil-only wiring short;
4. The version with the LDC1612 also integrates an LIS2DW accelerometer and an AHT20 temperature sensor — all three chips share the I2C bus, minimizing wiring. The board costs only about 10 RMB to build. With the accelerometer on the coil close to the nozzle, resonance compensation works well. Note that the AHT20 requires upgrading to the latest Klipper version.
5. The coil's resonant frequency is around 5.6 MHz — a high coil frequency, using a 40 MHz active crystal oscillator. Measured with the coil 2 mm above the nozzle, the frequency change over 0-4 mm after Klipper calibration exceeds 400 kHz; the maximum probing distance is over 7 mm — it can even scan the bed through a textured build plate. Distance noise is down to 0.1 µm. At a z-offset of 1 mm, the frequency change is over 6 kHz per 0.04 mm — extremely sensitive. The coil mounting height is about 2 mm above the nozzle;

6. Bed-scanning video guide: see Bilibili — 3D printed eddy coil leveling open-source release and solving the "Eddy current sensor error" problem. I named this coil the Little Crab bed-scanning coil; I have produced a batch of them — purchases welcome;

7. Klipper's eddy driver was upgraded in January 2026 to support the tap function, similar to IDM's touch mode — no AHT20 temperature sensor needed, no temperature calibration, automatic Z offset. As of 2026-05-02 automatic tap-threshold measurement is supported. Tap introduction video:  Introduction to Klipper's built-in eddy leveling tap mode (the video predates the update but the steps are about the same)

8. Temperature drift refers to drift during contactless homing. Over the full temperature range drift is about 0.2 mm. With tap-mode nozzle endstopping you don't need to worry about drift — tap is algorithm-based: as the nozzle approaches the bed the frequency keeps rising; once the nozzle touches the bed, the frequency growth slows and finally stops. The algorithm finds the inflection point where the frequency growth changes — that's where the nozzle touched the bed.

9. Questions? Join the QQ group: 1057494383. Latest tutorial at:  https://demo.chengxg.top/pangxie/#/articles/eddy_coil 

 

I. Error message roundup:

1. Unable to obtain 'i2c_read_response' response

If this appears when you send LDC_CALIBRATE_DRIVE_CURRENT chip=eddy_probe, the chip has a cold solder joint, or the I2C pins are simply configured wrong.

2.  Failed calibration - incomplete sensor data

During machine testing, sending PROBE_EDDY_CURRENT_CALIBRATE CHIP=eddy_probe seems to calibrate fine, but this message appears when saving — also caused by a cold solder joint.

A likely cause is a cold solder joint on the intb_pin, or that pin being misconfigured. This standalone coil does not need the intb_pin configured.

3. Failed calibration - frequency not increasing each step

Sending PROBE_EDDY_CURRENT_CALIBRATE CHIP=eddy_probe calibrates normally at first but this appears when saving. The soldering is fine — the problem is with the first few data points probed: frequency increases with distance. Possibly the heavy bed causes vibration when the nozzle is very close. Raise the nozzle to avoid vibrating against the bed at close range.

4.  Error during homing z: Eddy current sensor error

This one deserves a detailed explanation. The main cause is the LDC1612's amplitude error report: the drive current is calibrated at 20 mm above the bed, but the LDC1612's optimal coil amplitude is between 1.2V and 1.8V — that optimal drive current only holds at that height and temperature. When the height drops to around 2 mm, the drive current no longer applies and triggers the LDC1612 amplitude error report. Klipper has this error report enabled, so the moment an amplitude error occurs the LDC1612 reports it — that's why this error keeps appearing. We measure frequency; the amplitude doesn't need to be in the optimal range. So directly modify the Klipper code — change the LDC1612 register configuration to disable this error report.

The optimal drive current is affected by temperature, coil resonant frequency, sensor mounting height, and more. The optimal drive frequency measured at 20 mm doesn't cover these situations. This error report is very sensitive, and amplitude errors come in two flavors — amplitude-high and amplitude-low — while the drive current can only be set between 1 and 31, a limited range. It's very likely your mounting height is off by just a hair and you can never reach the optimal drive current — always too high or too low. That's why no matter how you adjust the drive current, this error keeps appearing. The error report must be disabled.

5. DigitalFilter require the SciPy module

Enabling tap mode required installing the SciPy library in early versions; later versions no longer need it.

Install command: ~/klippy-env/bin/pip install scipy -i https://pypi.tuna.tsinghua.edu.cn/simple

6. MCU'mcu' I2C request to addr 42 reports error START_NACK

Invalid Idc1612 id (got 0,0 vs 5449,3055). This is generally indicative of connection problems (e.g. faulty wiring) or a faulty Idc1612 chip

These errors mean I2C communication failed: 1. bad wiring 2. capacitors/diodes on the IO pins used 3. cold solder joints or a damaged chip.

7. Warning: Option'z_offset' in section 'probe_eddy_current eddy_probe' is deprecated

Klipper's eddy code was updated on 2026-05-02 and the z_offset parameter was renameddescend_z

8. Warning: ldc1612 eddy_probe: Should set 'max_sensor_hz' to at least 6153869

Klipper added the max-frequency parameter on 2026-05-12 with a default of 5M. My coil's frequency exceeds that, so add max_sensor_hz: 7000000 to the configuration.

9. !! Failed calibration - No usable data

If this appears during calibration, no data was obtained — most likely a wiring or soldering problem.

10. !! Error during homing stepper_z: Communication timeout during homing

If this appears during homing — especially with a low-clock MCU like the STM32F072 — check whether the MCU load is maxed out. The latest Klipper raised the LDC1612 polling rate from 250/s to 400/s. In that case you need to edit the code to lower the rate.
11.  !! Unable to detect tap: insufficient slope delta (-36983.054918 vs 30633.703000)
The tap-mode threshold is wrong. Use PROBE_ACCURACY METHOD=tap tap_threshold=40000 to find the tap_threshold value manually  
12.  !! Unable to detect tap: invalid depress distance (0.020411 vs 0.030000:0.250000) 
 In tap-mode detection the press-down distance was wrong — not within 0.03-0.25. May be related to bed rigidity. If you really can't tune it, edit this error check in klippy\extras\probe_eddy_current.py and widen the accepted range.
13.  !! Eddy: CLKIN frequency too low: 0.001 < 0.002
I2C communication is unstable — the interval between data points is inconsistent. Check whether USB or CAN communication is dropping packets badly, and whether MCU load is maxed out during probing.
 

II. Modifying the Klipper eddy driver code:

Klipper officially tested with BIQU's eddy, whose parameters differ from my coil, so some code configuration needs changing. Klipper has been updated recently — check this; if you get no errors you can skip the changes.

1. SSH in and locate the Klipper directory
Open the /klipper/klippy/extras/ldc1612.py file
 
2. Modify the LDC1612 register configuration
SETTLETIME = 0.0002  # originally 0.005, change to 0.0002 — ensures the LDC1612 still returns data if the coil wire breaks, so you don't crash. Otherwise, after a wire break the LDC1612 returns nothing and Klipper waits so long it crashes the nozzle.
self.set_reg(REG_ERROR_CONFIG, (0x1c << 11) | 1)  # modify the REG_ERROR_CONFIG register — originally 0x1f, change to 0x1c — to disable the amplitude error report and fix the sensor error
self.data_rate = 400 # LDC1612 polling rate. Klipper's current default is 400, which stresses low-clock MCUs like the STM32F072 — MCU load may max out, in which case change it to 250
 
3. Restart Klipper for the changes to take effect
After editing, save the file and restart the Klipper service (in Fluidd, click restart Klipper service in the top-right corner)

 

III. Commands for first-time eddy calibration:

1. Drive-current calibration command: LDC_CALIBRATE_DRIVE_CURRENT CHIP=eddy_probe

Do not calibrate the drive current 20 mm above the bed — calibrate with the nozzle close to the bed, at a height of about 2 mm. It doesn't need to be exact, since the amplitude error report is already disabled.

2. Eddy frequency-height calibration command: PROBE_EDDY_CURRENT_CALIBRATE CHIP=eddy_probe

① Before calibrating, first manually level the bed — it must not be badly tilted. Home X and Y first; for Z you can set a position using step ③ below.

② If you plan to use this eddy probe as a virtual Z endstop, first heat the bed to 80 °C and the nozzle to 150 °C, keeping the nozzle clean;

③ If you currently have no Z endstop, set the current Z position with SET_KINEMATIC_POSITION Z=<maximum Z height> , so you can skip Z homing.

④ Then run LDC_CALIBRATE_DRIVE_CURRENT CHIP=eddy_probe; Klipper enters the manual probe page — use it to jog the Z axis down until the nozzle is close to the bed.

⑤ If this will be your Z endstop, you must nail the feeler-paper feel precisely. If not, close is good enough — even 0.2 mm off doesn't matter;

⑥ Once done, Klipper automatically records the height-frequency relationship; just save the configuration.

3. Tap-mode threshold calibration command: PROBE_EDDY_CURRENT_TAP_CALIBRATE TAP=xxx

The 2026-05-02 Klipper update supports automatic measurement — you must first comment the parameter out and use the commands to find it.

① Make sure both the nozzle and the bed surface are clean. Power on the printer, home it, move the toolhead to a position near the center of the bed, and make sure the nozzle is 3-10 mm above the bed.

② The next step is to command the nozzle to touch the bed. There is always some risk in this process, so be ready to trigger an emergency stop (M112) at any time in case the probing descent does not stop after touching the bed. When ready, run:PROBE_EDDY_CURRENT_TAP_CALIBRATE TAP=guessThis command makes an initial rough guess of the tap_threshold value based on the data analyzed during the main probe calibration, then performs the corresponding “gentle tap probe”. Ideally the command lowers the probe until it touches the bed, then lifts off and reports a valid probe result.

③ The next step is to run the gentle tap probe again with the “refined” threshold setting. The tool uses information collected from the previous successful tap probe to determine this improved threshold. Make sure the nozzle is near the center of the bed, 3-10 mm above it, be ready for an emergency stop, then run:PROBE_EDDY_CURRENT_TAP_CALIBRATE TAP=refineIdeally this command also succeeds; otherwise see the troubleshooting section. If it succeeds, continue to the next step.

④ If the probe with the refined threshold succeeds, the next test verifies the threshold's stability across multiple probes. Make sure the nozzle is near the center of the bed, 3-10 mm above it, be ready for an emergency stop, then run:PROBE_EDDY_CURRENT_TAP_CALIBRATE TAP=verifyThis command probes the bed five times in a row. Ideally it also succeeds; otherwise see the troubleshooting section. If it succeeds, continue.

⑤ If all the above steps succeed, run SAVE_CONFIG to save the tap_threshold parameter to the printer.cfg file. Calibration is now complete.

If calibration errors out with a wrong threshold and you have to find it manually, don't use the automatic commands — use PROBE_ACCURACY METHOD=tap tap_threshold=40000 to find it by hand

IV. About temperature drift:

1. Without an enclosure, temperature drift is low — usually under 0.04 mm, though it varies and is hard to promise.

At z-offset = 1 mm, with the bed going from room temperature to 100 °C and the eddy coil from room temperature to 60 °C, the frequency change is 3 kHz and the resulting Z offset error is about 0.02 mm — minor, so it can be used as a Z endstop.

2. In an enclosure, temperature drift is unacceptable.

At z-offset = 1 mm, with the bed from room temperature to 108 °C and the eddy coil from room temperature to 80 °C, long-term frequency drift can reach 26 kHz, giving a Z offset error of about 0.2 mm — unacceptable. How much it drifts depends on your machine. Drift mainly occurs as the eddy temperature passes 65-80 °C. Under an enclosure, drift should be related to the whole printer structure's drift — the coil alone wouldn't drift this much. But if the coil mount and the entire toolhead drift, that's rough — the longer it sits hot, the more it deforms.

3. Doing temperature calibration

See the Klipper docs for the procedure — calibrate every 3-4 °C of coil temperature. Very time-consuming. And because drift isn't only related to coil temperature — if the whole machine deforms, temperature calibration won't fix it. Enclosures are rough. Now that tap mode exists, temperature calibration is no longer necessary.

Frequency drift chart while heating from room temperature to a 108 °C bed. This machine is enclosed, so drift is large — over 26 kHz of frequency drift, a 0.2 mm error, possibly related to how many printed parts my machine has.

My other machine, heated to 108 °C the same way, semi-enclosed: full-range drift is much smaller — under 8 kHz of frequency drift, about a 0.05 mm error.

[probe_eddy_current my_probe]

#samples: 3
#samples_tolerance: 0.025
#samples_tolerance_retries: 3
#tap_threshold: 0 # 0 means tap is disabled; automatic measurement supported since 2026-05-02, so comment this out first

It's the  tap_threshold: 0 parameter — the default 0 disables tap. The tap threshold must be set correctly or you'll get errors. The latest Klipper versions no longer need the scipy library — the updated algorithm doesn't use it.

The tap_threshold value used to be tens to hundreds; Klipper recently changed the threshold unit and the value became 50× larger.

The 2026-05-02 Klipper update supports automatic measurement — comment the parameter out first and use the commands to find it.

Automatic tap-threshold search — run these three commands in order:

1. Rough tap threshold calibration: PROBE_EDDY_CURRENT_TAP_CALIBRATE TAP=guess

2. Precise tap threshold calibration: PROBE_EDDY_CURRENT_TAP_CALIBRATE TAP=refine

3. Tap threshold verification, then save: PROBE_EDDY_CURRENT_TAP_CALIBRATE TAP=verify

If calibration errors out with a wrong threshold and you have to find it manually, don't use the automatic commands — use PROBE_ACCURACY METHOD=tap tap_threshold=40000 to find it by hand

VII. About coil design:

The coil shape has negligible effect — octagonal, circular, or superellipse coils all work about the same.

To that end I also built an online tool for designing superellipse coils:  https://demo.chengxg.top/eddy_coil_designer.html

TI's official coil design tool: https://webench.ti.com/wb5/LDC/#/spirals

My LDC1612 coil-frequency real-time online monitor sensor:  https://oshwhub.com/cxg01/3d-printer-weighing-hot-bed-sensor,  it can also be used as an ordinary proximity switch.
